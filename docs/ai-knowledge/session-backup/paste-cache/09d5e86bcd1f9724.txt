==================================================
0. سطح تلاش و Reasoning
==================================================

این Phase یک مرحله Research-Critical است.

Effort / Reasoning را روی:

Maximum / Highest

قرار بده.

در صورت وجود چند سطح Reasoning، بالاترین سطح موجود را انتخاب کن.

در این Phase:

- عمق تحلیل
- مقایسه گزینه‌ها
- کشف failure modeها
- بررسی Counter-Evidence
- scientific validity
- و دقت تصمیم‌سازی

از سرعت مهم‌تر هستند.

Maximum Effort فقط برای کیفیت تحلیل است و به هیچ‌وجه اجازه تغییر فایل، تغییر Scope، اجرای کد یا Implementation ایجاد نمی‌کند.

7. بدون تأیید انسانی آن را اجرا نکن.

اصل:

Scientific Validity
+
Maximum Preservation of Approved Scope
+
Minimum Necessary Correction

5. سیاست جست‌وجوی خارجی
==================================================

Corpus داخلی نقطه شروع اصلی است، اما کامل یا به‌روز فرض نمی‌شود.

هرجا Evidence موجود برای یک تصمیم کافی نیست، جست‌وجوی خارجی و به‌روز انجام بده.

به‌خصوص برای:

- PDA/DDA
- Leakage modelling
- PPO justification
- Reward design
- Safe/Constrained RL
- Baselines
- Demand Uncertainty
- Generalization
- Network selection
- 2025–2026 prior work

### قانون حیاتی:

به یک سایت، API یا موتور جست‌وجوی خاص وابسته نباش.

اگر یک منبع یا سرویس:

- 403
- 404
- 429
- Rate Limit
- Paywall
- API unavailable
- Tool unavailable
- PDF unavailable
- Extraction failure

داد:

1. چند بار بی‌فایده retry نکن.
2. منبع یا مسیر جست‌وجوی دیگری انتخاب کن.
3. تا جای ممکن از منابع مستقل استفاده کن.

اولویت منابع خارجی:

1. صفحه رسمی ناشر
2. DOI / Crossref
3. OpenAlex
4. Semantic Scholar
5. صفحه رسمی دانشگاه یا پژوهشگر
6. Repository دانشگاهی
7. Preprint معتبر
8. داده/کد رسمی پژوهش
9. سایر منابع علمی معتبر

اگر یک سرویس در دسترس نیست:

API unavailable
≠
Paper does not exist

Search result not found
≠
No prior work exists

اگر مقاله هنوز قابل تأیید نیست:

- Pending Verification علامت بزن.
- از نتیجه‌گیری قطعی استفاده نکن.
- محدودیت را در گزارش ذکر کن.

برای هر گزینه:

==================================================
10. PDA vs DDA
==================================================

این یک تصمیم Research-Critical است.

### DDA

بررسی:

- assumptions
- pressure deficiency behavior
- demand treatment
- leakage consequences
- risk of false improvement

### PDA

بررسی:

- pressure-demand relation
- physical realism
- parameterization
- leakage interaction
- computational impact
- validation requirements

سپس مشخص کن:

- آیا PDA ضروری است؟
- آیا DDA در این پروژه خطر ایجاد می‌کند؟
- آیا alternative یا hybrid formulation ارزش بررسی دارد؟

حداقل 2 گزینه را مقایسه کن.

هیچ‌کدام را بدون Evidence قطعی نکن.

- sensitivity

- disadvantages

25. Scientific Validity
==================================================

### Construct Validity
آیا metricها واقعاً construct موردنظر را می‌سنجند؟

### Internal Validity
آیا comparisonها fair هستند؟

### External Validity
آیا نتیجه‌ها قابل تعمیم‌اند؟

### Reproducibility
آیا experiment قابل تکرار است؟

همچنین:

### Operational / Physical Validity
آیا actionهای agent از نظر سیستم واقعی قابل اجرا هستند؟

32. Decision Gate
==================================================

در انتهای گزارش هر تصمیم را در یکی از این دسته‌ها قرار بده:

### READY TO LOCK
Evidence کافی و ریسک قابل مدیریت.

### NEEDS RESEARCHER DECISION
چند گزینه علمی قابل دفاع وجود دارد.

### NEEDS ADVISOR APPROVAL
ممکن است با Proposal/Seminar یا Scope مصوب تعارض داشته باشد.

### NEEDS MORE EVIDENCE
شواهد کافی نیست.

==================================================
33. هیچ Implementation
==================================================

این Phase فقط Design و Review است.

ممنوع:

- نوشتن کد
- ایجاد Environment
- ساخت Reward در کد
- انتخاب Network در فایل
- نصب dependency
- اجرای experiment
- تغییر Proposal
- تغییر Seminar
- تغییر Scope
- حذف یا اصلاح شواهد قبلی

هیچ فایل پروژه را تغییر نده.

==================================================
34. پایان Phase
==================================================

بعد از ارائه گزارش:

متوقف شو و منتظر دستور بعدی من بمان.

هدف این Phase:

«طراحی یک روش‌شناسی علمی، دقیق، قابل اجرا، reproducible و قابل دفاع، با استفاده از تمام شواهد موجود و با حفظ Scope مصوب پروژه.»

اگر شواهد نشان دادند بخشی از Proposal یا Seminar علمی مشکل دارد، آن را پنهان نکن.

اگر یک Recommendation خارج از Scope است، آن را صریحاً Scope-Expanding علامت بزن.

اگر Evidence کافی نیست، عدم‌قطعیت را اعلام کن.

اگر یک منبع محدودیت دسترسی دارد، از منبع معتبر دیگری استفاده کن یا Pending Verification ثبت کن.

هرگز نبود دسترسی به یک منبع را با نبود خود آن منبع اشتباه نگیر.
