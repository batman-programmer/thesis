==================================================
تنظیم سطح تلاش و Reasoning
==================================================

این Phase یک Deep Literature Review و تصمیم‌سازی پژوهشی با اهمیت بالا است.

برای این Phase از بالاترین سطح تلاش و عمیق‌ترین سطح Reasoning موجود استفاده کن.

اگر در تنظیمات سیستم سطوح مختلفی مانند Effort / Reasoning وجود دارد، بالاترین سطح ممکن یعنی Maximum / Highest را انتخاب کن.

در این Phase سرعت اولویت اصلی نیست؛ کیفیت، دقت و جامعیت تحلیل اولویت دارد.

ترجیح می‌دهم:

- تحلیل عمیق‌تر
- بررسی منابع بیشتر
- مقایسه دقیق‌تر
- جست‌وجوی گسترده‌تر برای Counter-Evidence
- بررسی دقیق‌تر نزدیک‌ترین کارهای قبلی
- کشف مفاهیم و پژوهش‌هایی که احتمالاً من ندیده‌ام
- بررسی دقیق‌تر تناقض‌ها
- و گزارش شفاف‌تر عدم‌قطعیت

انجام شود، حتی اگر مصرف Token و زمان بیشتری لازم باشد.

Maximum Effort فقط برای کیفیت تحلیل است و به‌هیچ‌وجه به معنی اجازه تغییر فایل، تغییر Methodology، تغییر Scope یا اجرای Implementation نیست.

### Targeted Review
برای منابعی که به مسئله، روش، Algorithm یا Contribution پروژه نزدیک هستند.

### Deep Review
برای:

- نزدیک‌ترین رقیبان علمی
- مقالات بنیادی
- مقالاتی که ممکن است Novelty را رد کنند

- مقالاتی که نتایج متناقض یا محدودیت‌های مهم دارند

در گزارش نهایی دقیقاً اعلام کن:

- چند منبع Screening شده
- چند منبع Targeted Review شده
- چند منبع Deep Review شده

و اگر یک منبع به‌علت محدودیت استخراج متن فقط در حد abstract یا بخش محدودی بررسی شده، این موضوع را صریحاً اعلام کن.

9. Counter-Evidence
==================================================

این بخش اجباری است.

برای هر ادعای مهم عمداً دنبال شواهد مخالف بگرد.

به‌خصوص بررسی کن آیا شواهدی وجود دارد که:

- PRV + Pump + DRL قبلاً انجام شده باشد.
- PPO قبلاً در شرایط بسیار مشابه استفاده شده باشد.
- Multi-objective Reward به‌خودی‌خود Novelty نباشد.
- Demand Uncertainty قبلاً به‌صورت مشابه بررسی شده باشد.
- DDA برای مسئله ما مشکل‌زا باشد.
- PDA لازم یا مناسب‌تر باشد.
- انتخاب شبکه نتایج را شدیداً تحت تأثیر قرار دهد.
- Baseline فعلی ضعیف باشد.
- PPO نسبت به SAC/DDPG/TD3 یا روش‌های دیگر مزیت مشخصی نداشته باشد.
- Reward باعث Reward Hacking یا unintended behavior شود.
- نتایج یک شبکه قابل تعمیم به شبکه‌های دیگر نباشند.
- Simulation results بیش از حد خوش‌بینانه باشند.

اگر Counter-Evidence پیدا کردی، آن را پنهان نکن.

هدف، تأیید پروژه نیست؛ هدف، کشف آسیب‌پذیری‌های علمی آن است.

20. تفاوت Recommendation و Decision
==================================================

در این Phase فقط Recommendation بده.

Recommendation باید شامل:

- Evidence
- Reasoning
- Alternatives
- Risk
- Confidence

باشد.

اما هنوز هیچ Decision نهایی نگیر.

به‌خصوص:

- Network انتخاب نکن.
- State نهایی نکن.
- Action نهایی نکن.
- Reward نهایی نکن.
- Baseline نهایی نکن.
- Methodology را تغییر نده.
- Scope را تغییر نده.

این تصمیم‌ها در Phase بعدی و با استفاده از Methodology Review و Novelty Check بررسی می‌شوند.

==================================================
21. Proposal/Seminar Conflict Protocol
==================================================

اگر بین Proposal/Seminar و Evidence تعارض وجود دارد:

1. دقیقاً بگو Proposal/Seminar چه می‌گوید.
2. Evidence چه می‌گوید.
3. تعارض دقیقاً کجاست.
4. نوع مشکل چیست:
   - wording
   - interpretation
   - implementation
   - methodological
   - experimental
   - fundamental scientific
5. شدت مشکل چیست.
6. آیا Minimum Scientifically Valid Correction وجود دارد.
7. آیا اصلاح بدون تغییر Scope ممکن است.
8. اگر تغییر Scope لازم است، چه چیزی تغییر خواهد کرد.
9. آیا نیاز به تصمیم پژوهشگر/استاد دارد.

اصل تصمیم:

Scientific Validity
+
Maximum Preservation of Approved Scope
+
Minimum Necessary Correction

هیچ تعارضی را پنهان نکن و هیچ‌یک را خودسرانه جایگزین دیگری نکن.

==================================================
22. جلوگیری از Scope Creep
==================================================

اگر در ادبیات ایده‌ای جذاب پیدا کردی:

صرفاً به دلیل جالب بودنش پیشنهاد تغییر مسیر نده.

قبل از هر پیشنهاد توسعه:

- آیا ضروری است؟
- آیا مستقیماً به Research Question مربوط است؟
- آیا داخل Scope مصوب می‌گنجد؟
- آیا یک مسئله علمی موجود را حل می‌کند؟
- آیا Alternative ساده‌تری وجود دارد؟
- هزینه و ریسک آن چقدر است؟

هدف:

Maximum Scientific Quality
با
Minimum Unnecessary Complexity

است.

==================================================
23. پایان Phase
==================================================

بعد از تکمیل Deep Literature Review:

- هیچ فایل پروژه را تغییر نده.
- هیچ کدی ایجاد یا اصلاح نکن.
- هیچ آزمایشی اجرا نکن.
- هیچ Methodology را تغییر نده.
- هیچ شبکه‌ای انتخاب نکن.
- هیچ State/Action/Reward را نهایی نکن.
- Proposal یا Seminar را اصلاح نکن.
- Scope را تغییر نده.
- هیچ نتیجه‌ای را به‌صورت project decision ثبت نکن.

فقط گزارش نهایی را ارائه کن.

بعد از ارائه گزارش، متوقف شو و منتظر دستور بعدی من بمان.

هدف این Phase این است:

«تبدیل Proposal + Seminar + 42 منبع + ادبیات جدید به یک نقشه شواهد علمی عمیق و قابل دفاع برای طراحی نهایی روش‌شناسی پروژه.»

اگر شواهد نشان دادند یکی از فرضیات من احتمالاً اشتباه است، واضح بگو.

اگر شواهد کافی نیست، عدم‌قطعیت را واضح بگو.

اگر پژوهش مهمی پیدا کردی که احتمالاً من ندیده‌ام، آن را برجسته کن.

اگر ادعایی فقط بر اساس نبودن یک مقاله در جست‌وجوی فعلی است، آن را به‌عنوان «عدم اثبات» گزارش کن، نه «اثبات نبودن».

در تمام طول Phase، Scientific Integrity و Evidence بر سرعت، راحتی و توافق مقدم هستند.
