6. بررسی کامل PDFها و Evidence Extraction
==================================================

به text extraction صرفاً اعتماد نکن.

اگر متن PDF ناقص، به‌هم‌ریخته یا ناقابل استفاده بود، بررسی کن آیا با مشاهده تصویری صفحه می‌توان اطلاعات را بازیابی کرد.

این مورد مخصوصاً برای:

- جدول‌ها
- شکل‌ها
- نمودارها
- فرمول‌ها
- architecture diagrams
- network diagrams
- captions
- مقایسه‌های جدولی
- متن فارسی/RTL
- بخش‌هایی که extraction آن‌ها اشتباه است

اهمیت دارد.

### قانون قطعی:

اگر چیزی از text extraction مشخص نیست:

- حدس نزن.
- آن را به‌عنوان fact معرفی نکن.
- ابتدا صفحه مربوط را شناسایی کن.
- در صورت امکان خود صفحه/تصویر را بررسی کن.
- اطلاعات قابل مشاهده را استخراج کن.
- اگر باز هم مشخص نیست، صریحاً بنویس «Evidence unavailable / incomplete».

### مخصوص Proposal و Seminar

اگر یک جدول، شکل، نمودار یا فرمول مهم در Proposal یا Seminar فقط به‌صورت ناقص استخراج شد:

1. شماره صفحه را پیدا کن.
2. caption را ثبت کن.
3. خود صفحه/تصویر را بررسی کن، اگر امکانش هست.
4. محتوای جدول/شکل را تا حد امکان دقیق استخراج کن.
5. مشخص کن این مورد برای Literature / Methodology / Novelty / Research Gap یا تصمیم دیگری مهم است.
6. اگر قابل مشاهده نیست، حدس نزن و آن را Pending Evidence علامت بزن.

هیچ نتیجه مهمی را فقط بر اساس caption یک جدول یا شکل استخراج نکن.

10. Counter-Evidence
==================================================

این بخش اجباری است.

برای هر contribution یا assumption مهم عمداً دنبال evidence مخالف بگرد.

به‌خصوص بررسی کن:

- آیا PRV + Pump + DRL قبلاً انجام شده؟
- آیا PPO در شرایط تقریباً مشابه قبلاً استفاده شده؟
- آیا Multi-objective Reward واقعاً contribution است؟
- آیا Demand Uncertainty قبلاً با همین framing بررسی شده؟
- آیا PDA یا DDA می‌تواند validity را تحت تأثیر قرار دهد؟
- آیا baseline فعلی ضعیف است؟
- آیا PPO نسبت به SAC/TD3/DDPG یا دیگر روش‌ها برتری اثبات‌شده دارد؟
- آیا نتایج شبکه خاص بیش از حد به topology وابسته‌اند؟
- آیا reward می‌تواند reward hacking ایجاد کند؟
- آیا simulation assumptions باعث نتایج غیرواقعی می‌شوند؟
- آیا generalization واقعاً وجود دارد؟

اگر evidence مخالف وجود داشت، آن را برجسته کن.

هدف، تایید پروژه نیست.

هدف، شکست‌دادن فرضیات ضعیف قبل از Implementation است.

19. Proposal/Seminar Conflict Protocol
==================================================

اگر Proposal/Seminar با شواهد تعارض داشت:

1. Proposal/Seminar چه می‌گوید؟
2. Evidence چه می‌گوید؟
3. تعارض چیست؟
4. نوع مشکل:
   - wording
   - interpretation
   - implementation
   - methodological
   - experimental
   - fundamental scientific
5. شدت مشکل
6. Minimum Scientifically Valid Correction
7. آیا بدون تغییر Scope قابل اصلاح است؟
8. آیا تغییر Scope لازم است؟
9. آیا نیاز به تصمیم پژوهشگر/استاد دارد؟

اصل:

Scientific Validity
+
Maximum Preservation of Approved Scope
+
Minimum Necessary Correction

هیچ تعارضی را مخفی نکن.

- Baseline نهایی نکن.
- Methodology را تغییر نده.
- Scope را تغییر نده.
