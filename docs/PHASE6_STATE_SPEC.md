## 7.1 The control loop and the timing convention

- Control step Δt = **1800 s** (EPANET report/hydraulic cadence) [VALIDATED FACT].
  A 96 h episode = 192 control decisions (report points t = 0 … 345600 s).
- **Timing convention [ENGINEERING DECISION]:** the observation `o_t` is built from
  the hydraulic state *after* the simulator has advanced to time `t` under the
  **previous** action `a_{t-1}`, and *before* the agent's action `a_t` is applied.
  Consequently the "previous commanded" fields in `o_t` hold `a_{t-1}`. This is the
  standard `(observe → act → step)` ordering and guarantees the observation never
  contains the effect of the action currently being chosen, nor any future state.
- At reset (`t = 0`) there is no previous action; the "previous commanded" fields
  are initialized from the actuators' **native initial settings** loaded from the
  INP (the 5 PRV nominal setpoints and the pump initial speeds), mapped through the
  same normalization [ENGINEERING DECISION].

| Index range | Block | Dims | Normalized range |

| `[121:123]` | Tank levels — TANK-130, TANK-131 | 2 | `[0, 1]` |

## 7.3 Per-variable justification (brief §13)

1. **Service-node pressures (121)** — the primary observable. Background leakage is
   pressure-driven and the service constraint is pressure-defined (≥20 psi), so node
   pressures are the direct signal for both objective and constraint [VALIDATED
   FACT: 121 service nodes]. Full-field pressure observability is a **[RESEARCH
   ASSUMPTION]** standard for simulation-based WDN-DRL studies; a realistic reduced
   sensor set (a handful of gauges) is a documented future ablation, NOT adopted now
   (would change scope). Neighboring-node pressures are partially correlated
   (redundant), which a future sensor-reduction or GNN could exploit [HYPOTHESIS TO
   TEST]; the flat 121-vector is the defensible baseline.
2. **Tank levels (2)** — the network's slow integrator / memory. Pump STATUS rules
   fire on tank levels, so the same pressures with different tank levels evolve
   differently; omitting them would break the Markov approximation. **Essential**
   [ENGINEERING DECISION grounded in the native rule structure — VALIDATED FACT].
3. **Previous commanded PRV setpoints (5)** — with the APPROVED absolute encoding,
   the actuator holds the last commanded setpoint between decisions, so this is
   effectively the current physical setpoint of each regulating valve. Lets the
   policy make smooth relative adjustments and interprets the pressures it sees as a
   consequence of these setpoints [ENGINEERING DECISION].
4. **PRV `is_active` flags (5)** — the realized-state counterpart to (3). A PRV
   commanded above the available upstream head cannot regulate and goes Open (not
   regulating); the flag distinguishes "regulating at the commanded value" from
   "wide open / uncontrolled". Compact realized-state signal (brief §15)
   [ENGINEERING DECISION; EPANET LinkStatus Active=2 vs Open=1 — VALIDATED FACT].
5. **Previous commanded pump speeds (2)** — what the agent asked for last step.
6. **Pump realized speeds (2)** — the speed actually in effect after native STATUS
   rules ran; **0 = pump CLOSED**. Because the native `STATUS IS OPEN` rule resets
   speed to 1.0 (G12, VALIDATED FACT, `p6_s4_pump_strategy.json`), realized can
   differ sharply from commanded; exposing both lets the policy learn the override
   rather than be confused by it. Folding status into realized speed (0 = closed)
   avoids a redundant status flag [ENGINEERING DECISION].
7. **Time-of-day (sin, cos) (2)** — a cyclical encoding of the 24 h diurnal demand
   pattern; see §7.5 and §7.9 [ENGINEERING DECISION].

## 7.4 Previous commanded vs realized actuator state (brief §15)

The design deliberately carries **both** representations, because for this network
they differ and the difference is informative:

| Actuator | Previous **commanded** (agent asked) | **Realized** (after native rules) |
|---|---|---|
| PRV | setpoint block `[123:128]` | `is_active` flag `[128:133]` (+ node pressures) |
| Pump | speed block `[133:135]` | realized speed `[135:137]`, 0 = closed |

- Commanded ≠ realized for a **pump** whenever the native `STATUS IS OPEN` rule
  reopens a pump and resets its speed to 1.0 [VALIDATED FACT, G12].
- Commanded ≈ realized setting for a **PRV** while it is Active; when it cannot
  regulate it reads Open and the `is_active` flag drops to 0.
- Reporting the commanded value as if realized is explicitly forbidden
  (`PHASE6_ACTION_SPACE_SPEC.md` §9.7). The env's `info` dict will additionally log
  the full commanded/realized/status triple per actuator for auditing (not part of
  the observation vector).

## 7.5 Demand handling (brief §14) — options A–E

The thesis studies control **under uncertain demand**; how much demand the agent
observes is therefore a first-order scientific choice, not a convenience.

| Option | What the agent would see | Assessment |
|---|---|---|
| **A. None (adopted)** | no explicit demand; infer it from pressures, tank dynamics and time-of-day | Preserves the "uncertain demand" framing (demand stays hidden); realistic (no per-node demand telemetry exists in real WDNs); bounded dimension. |
| B. Instantaneous total | current network demand now | Realistic proxy (production flow is metered) but reveals the very quantity the study treats as uncertain at time `t`; weakens the framing. Kept as a documented ablation. |
| C. Aggregate/zone | current zonal demand | As B, plus a zone-partition assumption not in scope. |
| D. Local nodal | current per-node demand | **Rejected** — unrealistic telemetry and effectively leaks the hidden state; would trivialize the problem. |
| E. History/forecast | recent or future demand | Forecast is **FORBIDDEN** (future info, §7.10). A short *past* demand history is a possible future ablation only. |

**Decision [ENGINEERING DECISION + RESEARCH ASSUMPTION]: Option A.** The agent
receives no explicit demand signal. Time-of-day (§7.9) supplies the *diurnal prior*
(demand is 24 h-periodic), and the observed pressures + tank levels are the
*consequences* of the realized demand. The agent must adapt to demand it cannot
directly see — which is exactly the thesis premise.

- **Counter-argument / risk [HYPOTHESIS TO TEST]:** without any demand signal the
  policy may under-react to fast demand transients (partial observability, §7.9).
  If STEP-13+ shows this hurts learning, the *first* documented remedy is adding the
  metered **total inflow** (Option B, one scalar) — a realistic sensor — before any
  richer demand exposure. This is recorded as a future ablation, not adopted now.
- **Absolute constraint [carried from the brief]:** the agent must **NEVER** receive
  future demand under any option.

## 7.6 Connector-node exclusion (brief §16)

The 5 connector artefacts **JUNCTION-105, -106, -109, -110, -128** (declared
elevation 0.0 ft AND zero base demand) are **excluded from the pressure feature
block** but **remain in the hydraulic model** and in the solve [VALIDATED FACT; same
rule as Phase 5 gate 10 / `p6_s3` `service_nodes()`]. They are non-physical junctions
whose pressures are meaningless as service signals; including them would inject
artefact values (one reads > 500 psi at nominal). Test 8 enforces their absence
from the observation.

## 7.7 Normalization (brief §17)

Principle [ENGINEERING DECISION]: **fixed physical normalization only** — every
constant is either a physical model property (tank levels, actuator bounds) or a
fixed chosen band. **No data-derived running statistics** (mean/std over collected
transitions), which would couple normalization to the training data and risk
train/eval leakage.

| Variable | Raw unit / range | Transform | Norm. range | Clip / out-of-range |
|---|---|---|---|---|
| Node pressure | psi; observed ≈ 4–288, adverse can go negative | `(p + 20) / 320` | `[0, 1]` | clip; `< −20 → 0`, `> 300 → 1` |
| Tank level | ft; per-tank `[min,max]` = 130:`[0,32.1]`, 131:`[0,41.9]` | `(l − min)/(max − min)` | `[0, 1]` | clip |
| Prev cmd PRV setpoint | psi; per-valve approved `[lower,upper]` | `(s − lower)/(upper − lower)` | `[0, 1]` | commanded already clamped |
| PRV is_active | {Active, Open, Closed} | `1 if Active else 0` | `{0, 1}` | — |
| Prev cmd pump speed | rel.; per-pump `[lower,1.10]` | `(v − lower)/(1.10 − lower)` | `[0, 1]` | commanded already clamped |
| Pump realized speed | rel.; `{0}∪[lower,1.10]` | `v / 1.10` | `[0, 1]` | `0 ⇔ closed`, clip |
| Time-of-day | s of day `[0,86400)` | `sin,cos(2π·s/86400)` | `[−1, 1]` | exact, no clip |

- **Pressure band `[−20, 300]` psi [ENGINEERING DECISION].** Chosen to bracket the
  full measured service range (≈ 4–288 psi; probe p99 ≈ 184 psi) with head-room for
  adverse negative pressures and overshoot, *without* saturating the many high-head
  nodes (a narrower cap such as 120 psi would clip a large fraction of nodes to 1.0
  and destroy their resolution). A per-node fixed band derived from node elevation is
  a documented refinement [HYPOTHESIS TO TEST: would sharpen resolution near the
  20 psi service threshold]; not adopted now to keep one reproducible global band.
- Tank-level and actuator bounds are exact physical/approved constants — no
  data leakage possible [VALIDATED FACT].

## 7.8 dtype and shape stability (brief §18)

`float32`, fixed shape `(139,)` for every step of every episode — no
variable-length structures. The gymnasium `Box(low, high, shape=(139,),
dtype=float32)` is built in STEP 11 from `observation_bounds()`; `low = 0` on all
dims except the time-of-day pair (`−1`), `high = 1` everywhere. Tests 1–2 pin shape
and dtype across varied inputs.

## 7.9 Markov analysis (brief §19)

- The true EPS state is the full hydraulic state (all heads, tank levels, link
  statuses/settings) **plus the demand trajectory / stochastic multiplier**.
- The observation captures node pressures (↔ heads), tank levels (the dominant
  dynamic memory), actuator commanded+realized states, and time-of-day.
- **Not** captured: instantaneous nodal demands, the stochastic demand multiplier,
  pipe flows, and the (uncalibrated) leak flow.
- Therefore the process is a **partially observable MDP; the observation is a strong
  *approximate* sufficient statistic, not an exact Markov state** [ENGINEERING
  DECISION / honest limitation]. We do **not** force full Markovity: doing so would
  require injecting instantaneous demand, which is unrealistic and would remove the
  uncertain-demand challenge (§7.5).
- Because tank levels — the slow memory — *are* observed, single-step partial
  observability is expected to be mild [HYPOTHESIS TO TEST]. If instability appears
  in later training, the first documented remedy is a short observation history
  (frame-stack) or a recurrent policy; both are out of current scope (brief §27).

## 7.10 Future-information leakage audit (brief §20)

Checked, source by source:

- Pressures / tank levels — state **at** `t` (post previous action), not future. ✓
- Previous commanded / realized actuator state — strictly `t−1` / current. ✓
- Time-of-day — the **current** clock, a deterministic calendar feature, not a
  demand forecast. ✓
- Demand — Option A carries none; no forecast anywhere (§7.5). ✓
- Leak flow — deliberately **excluded** from the observation (uncalibrated,
  reward/eval-side quantity). ✓
- No reward, return, episode index, or end-of-episode marker is exposed. ✓

**Conclusion: no future-information leakage** in the proposed observation. The
`RawState` input contract contains no field naming a future/forecast/next-step or a
raw demand signal; Test 7 enforces this at the code level.

## 7.11 Deterministic observation builder (brief §21)

`src/env/state_builder.py` implements the design as a **pure, side-effect-free**
function `build_observation(config, raw) → np.ndarray`:

- no RNG, no wall clock, no I/O, no EPANET/WNTR/gymnasium import (numpy only);
- identical `(config, raw)` → bit-identical output (Test 5);
- missing keys raise `KeyError` (fail loud), never a silent default;
- `ObservationConfig` holds the fixed node ordering + all normalization constants;
  `observation_bounds()` returns the `Box` low/high arrays for STEP 11.

Validated by `tests/test_state_builder.py` — **9/9 passing** (stdlib `unittest`,
no pytest needed): shape-constant, dtype-constant, no-NaN/Inf, deterministic
normalization, same-state→same-obs, different-state→expected-diff,
no-future-information (contract), connector-exclusion, prev-action semantics.

## 7.14 Approval gate — decision D-P6-004 (PROPOSED)

This observation design is **PROPOSED, pending researcher approval** (CLAUDE.md
§17 step 10). Points a reviewer should explicitly accept or amend:

1. **Full 121-node pressure observability** (vs a realistic sensor subset).
2. **Demand Option A** (no explicit demand; time-of-day as diurnal prior).
3. **Fixed pressure band `[−20, 300]` psi** (vs per-node bands).
4. Carrying **both** prev-commanded and realized actuator state (dimension cost).
5. **Single-step (MLP) observation**, accepting approximate Markovity (no history).

Until D-P6-004 is approved, `observation_dim = 139` and the layout above are the
**working** design; the ordering will be frozen (like the action vector) on
approval. Earlier alternatives are preserved in this section and in
`docs/PHASE6_DECISION_REGISTER.md`.
